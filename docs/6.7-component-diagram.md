Sơ đồ trên mô tả kiến trúc hệ thống **IoT Smart Parking Management System (IoT-SPMS)**, bao gồm 3 khối chính: **IoT-SPMS Frontend (Client)**, **IoT-SPMS Backend (Server)**, và các **Hệ thống bên ngoài (External Systems)**.

### 1. IoT-SPMS Frontend (Client)

Đây là gói (package) chứa các thành phần giao diện người dùng, được xây dựng bằng **React + Vite** theo mô hình SPA. Frontend giao tiếp với backend thông qua **REST API** và đính kèm **JWT** bằng Axios interceptor.

Frontend được chia thành các component chính theo vai trò:

- **Authentication UI (Giao diện đăng nhập)**: mô phỏng luồng đăng nhập tập trung của trường.
  - **CAS-like Login**: trang đăng nhập SSO giả lập (`/cas`, `CasLoginPage.tsx`).
  - **Admin/Operator Login**: trang chọn phương thức đăng nhập và modal đăng nhập cho quản trị/nhân viên (`/login`, `LoginPage.tsx`).

- **Student/Staff Interface (Giao diện Sinh viên/Cán bộ)**: tập trung vào trải nghiệm cá nhân.
  - **Module Thanh toán cá nhân**: xem dư nợ, ước tính phí, trigger thanh toán BKPay cho kỳ hiện tại (`UserPortal.tsx`).
  - **Module Bản đồ bãi xe**: xem trạng thái slot theo zone, tình trạng cảm biến/slot (dùng chung với các vai trò khác) (`ParkingMapPage.tsx`).

- **Operator/Admin Interface (Giao diện Nhân viên/Quản trị)**: phục vụ vận hành và quản trị hệ thống.
  - **Module Dashboard**: thống kê tổng quan (tổng chỗ trống, chart theo tuần), hoạt động gần đây, cảnh báo cảm biến (`DashboardPage.tsx`).
  - **Module Bản đồ bãi xe**: giám sát theo zone/row/slot và dữ liệu IoT (`ParkingMapPage.tsx`).
  - **Module Vé tạm thời**: cấp vé khách, checkout khách vãng lai (`GateControl.tsx`).
  - **Module Quản lý thanh toán**: xem danh sách payment toàn hệ thống (lọc theo kỳ/trạng thái) (`PaymentAdminPage.tsx`).
  - **Module Báo cáo**: báo cáo theo kỳ, top user, daily chart, export PDF (`ReportsPage.tsx`, dùng `jspdf`).
  - **Module Admin**: quản lý user (tạo/sửa/vô hiệu hóa/reset mật khẩu), cấu hình bảng giá, xem audit log; có chức năng mock sync DATACORE (`AdminPage.tsx`).

Ngoài ra frontend còn có các component “core”:

- **AuthContext**: quản lý session JWT + user state (localStorage) và điều hướng sau login/logout.
- **Route Guard + Layout**: phân quyền route theo role (ADMIN/OPERATOR/STUDENT/STAFF) và hiển thị menu tương ứng.
- **i18n**: hỗ trợ song ngữ VI/EN bằng `react-i18next`.

### 2. IoT-SPMS Backend (Server)

Đây là gói component lõi, chịu trách nhiệm xử lý toàn bộ **business logic** và cung cấp **REST API** (NestJS). Backend được tổ chức theo module/service rõ ràng và có lớp bảo mật dùng chung (JWT guard + RBAC) cho toàn bộ tuyến API.

Các component chính:

- **REST API Layer (Controllers)**: cung cấp các endpoint `/api/*` cho frontend và một số “machine client” (IoT gateway).

- **Authentication Service**: xử lý đăng nhập, phát hành JWT, và cung cấp thông tin user hiện tại.
  - Ở bản MVP, xác thực được **mock** bằng cách so khớp `hcmutId + passwordHash` trong DB.
  - Về mặt kiến trúc, service này **requires** giao diện của **HCMUT_SSO** (production sẽ delegate validate/password đến SSO thật).

- **Parking Service (UC-1)**: xử lý nghiệp vụ check-in/check-out qua RFID.
  - Chống double-entry bằng cách kiểm tra session `ACTIVE`.
  - Ghi audit log để phục vụ truy vết.
  - Có ràng buộc SLA “mở barrier < 2s” được logging nếu vi phạm.

- **Visitor Service (UC-2)**: xử lý cấp vé tạm thời và checkout khách.
  - Tính phí theo pricing policy của “visitor_motorbike/visitor_car”.
  - Sinh `ticket_code` và lưu lịch sử ra/vào.

- **IoT Service (UC-3)**: nhận sự kiện cảm biến, cập nhật trạng thái slot, đánh dấu lỗi, và tính trạng thái LED theo zone.
  - Endpoint sensor event dùng **API key** (`x-iot-key`) thay vì JWT.
  - Có cơ chế fault tolerance: dữ liệu trễ quá `IOT_UPDATE_TIMEOUT_MS` sẽ bị flag lỗi.
  - Mô phỏng IoT thay đổi ngẫu nhiên để demo luồng realtime-like.

- **Billing Service (UC-4)**: tổng hợp phí theo kỳ, tạo payment, và xử lý hành động thanh toán.
  - Sinh payment theo `billingPeriod` (ví dụ `YYYY-MM`).
  - Tính phí dựa trên phiên gửi xe (sessions) + pricing policy.

- **Payment Queue Worker**: hàng đợi retry BKPay chạy nền.
  - Queue **DB-backed** bằng bảng `payment_jobs` (không phụ thuộc Redis/BullMQ).
  - Cron chạy mỗi 30s: lấy job `PENDING`, gọi BKPay (mock), retry theo exponential backoff, đánh dấu `DONE/FAILED`.

- **Admin Service (UC-5)**: cung cấp dashboard, báo cáo, quản lý user, pricing, và system log.
  - Có mock endpoint “sync DATACORE” để mô phỏng đồng bộ dữ liệu trường.

- **Data Access Layer (DAL)**: `PrismaService` trừu tượng hóa việc truy cập CSDL MSSQL, được inject vào các service.

### 3. External Systems (Hệ thống bên ngoài)

Đây là các thành phần độc lập mà hệ thống phụ thuộc vào (hoặc mô phỏng để phục vụ MVP):

- **Database (MSSQL Server)**: lưu toàn bộ dữ liệu nghiệp vụ (users, zones/slots, sessions, tickets, payments, pricing policies, system logs, payment jobs).

- **HCMUT_SSO (CAS/SSO)**: hệ thống xác thực tập trung.
  - Ở phiên bản hiện tại: UI mô phỏng CAS ở frontend và backend mock password trong DB.
  - Ở phiên bản production: Auth Service sẽ delegate xác thực sang SSO.

- **HCMUT_DATACORE**: hệ thống lõi dữ liệu người dùng của trường.
  - Hiện tại: đồng bộ được mô phỏng (mock) để phản ánh luồng tích hợp.

- **BKPay**: cổng thanh toán.
  - Hiện tại: được mock trong queue worker (tỉ lệ success/fail để test retry).
  - Production: thay bằng gọi API BKPay thật (dựa trên `BKPAY_URL`, `BKPAY_API_KEY`).

- **IoT Gateway / Sensors + LED board**: thiết bị gửi event (available/occupied/fault) và nhận trạng thái LED theo zone.

- **Gate System (RFID + Barrier)**: hệ thống cổng vào/ra và đầu đọc thẻ RFID gọi API check-in/out.
